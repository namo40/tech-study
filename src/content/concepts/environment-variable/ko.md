장면의 두 번째 단계는 쉬운 답이 도착하고, 그 답에 가격표가 붙어 있다는 것이 드러나는 자리입니다. 깨끗한 이미지에서 파드가 배포되고, 스토어에서 값이 올라오고, 프로세스가 코드 한 줄을 돌리기도 전에 `env` 슬롯이 가득 찹니다. 매력은 여기에 다 있고, 작은 매력도 아닙니다. 클라이언트 라이브러리도, 파일 시스템 배치도, 실패할 수 있는 시작 시점 호출도, 설정을 읽는 시점과 그것이 필요해지는 시점 사이의 순서 문제도 없습니다. 모든 언어와 모든 런타임과 모든 베이스 이미지가 환경 변수가 무엇인지에는 합의합니다.

그런데 환경이란 운영체제가 프로세스에게, 그리고 그 프로세스가 시작하는 모든 것에게 건네주는 메모리 한 덩어리입니다. 정의가 그렇고, 모든 누수는 그 정의에서 곧바로 따라 나옵니다. 마이그레이션을 돌리려고 셸을 띄우면 셸이 값을 가집니다. 사이드카 도우미, 헬스 체크 스크립트, `git` 호출을 띄우면 그것들도 각자 값을 가집니다. 크래시 덤프는 프로세스 메모리의 사본이므로 덤프가 값을 가집니다. 지원용으로 설정을 그려 주는 진단 엔드포인트, 환경을 잘못 잡은 곳에서 뜬 처리되지 않은 예외 페이지, 맥락을 남기겠다고 환경을 통째로 담기로 한 로깅 보강기, 전부 값을 가집니다. 그리고 그중 어느 것도 자신을 보안 경계라고 생각한 적이 없습니다. 환경은 환경인데도 새는 것이 아니라, 환경이 원래 하라는 일을 정확히 하고 있는 것입니다.

두 번째 비용은 시간입니다. 변수는 프로세스가 시작할 때 건네지고, 새 값을 다시 건네줄 장치는 없습니다. 그 덩어리가 프로세스 발밑에서 바뀌지 않는다는 것이 애초에 존재 이유이기 때문입니다. 장면이 네 번째 단계를 그렇게 그리는 이유가 여기 있습니다. 스토어가 버전을 바꾸면 마운트된 파일은 제자리에서 갱신되고, 환경 변수 쪽은 파드가 교체될 때까지 받았던 값을 그대로 쥐고 있습니다. 환경 변수 경로에서 회전은 설정 다시 읽기가 아니라 재시작이고, 재시작은 결과가 따라붙는 실제 사건입니다. 연결이 한꺼번에 끊겼다 붙고, 데워 놓은 캐시가 사라지고, 롤링 업데이트를 잡아야 하고, 워크로드가 단일 인스턴스라면 점검 시간까지 필요합니다.

그렇다고 환경 변수가 틀린 것은 아닙니다. 성질이 알려진 선택일 뿐이고, 내릴 값어치가 있는 선택은 원래 그런 것뿐입니다. 기능 플래그, 로그 수준, 공개된 엔드포인트 URL, 버킷 이름, 초 단위 제한 시간은 환경 변수에 속하고, 이런 값을 더 고급스러운 곳에 두는 것은 이득 없는 비용입니다. 리포팅 복제본까지 열어 주는 데이터베이스 암호, 세션 쿠키를 서명하는 키, 결제 사업자의 운영 API 키는 마운트된 파일이나 시작할 때 값을 받아 오는 클라이언트를 원합니다. 새느냐 안 새느냐의 차이가 부주의한 진단 페이지 하나와 없음의 차이이기 때문입니다.

규율이 강제되는 자리는 매니페스트이고, 강제하는 방법은 값을 절대 적지 않는 것입니다. 컨테이너의 `env` 항목은 리터럴을 담을 수 있는데, 담는 순간 비밀은 버전 관리에도, 렌더링된 모든 템플릿에도, 그것을 적용한 무언가의 감사 로그에도 들어갑니다. 대안은 한 줄 더 쓰는 것뿐입니다. 항목이 `secretKeyRef`로 스토어 항목의 이름을 부르고, 플랫폼이 시작할 때 그것을 풀어 줍니다. 이 구분은 코드 리뷰에서 눈에 보이고, 그것이 바로 눈에 보였으면 하는 자리입니다.

.NET이 환경 변수를 읽는 방식에 관해 하나 더 알아 둘 것이 있습니다. 구성 키는 계층이고 환경 변수는 평평하므로, 밑줄 두 개가 그 사이의 다리입니다. `ConnectionStrings__Orders`가 `ConnectionStrings:Orders`가 되고, 중첩된 옵션 객체를 잎사귀 하나씩 덮어쓸 수 있으니 배포가 나머지 구조를 알 필요가 없습니다. 환경 변수는 보통 소스 사슬의 마지막에 더해지므로 이 덮어쓰기가 JSON 파일보다 이기고, 그래서 이미지 하나가 두 클러스터에서 다르게 동작합니다. 개발자 기계에 실수로 설정된 변수가 파일의 값을 조용히 가려 버리는 이유도 같고, "컨테이너에서는 되는데 로컬에서는 안 된다"가 코드 버그보다 구성 우선순위 버그인 경우가 그렇게 많은 이유도 같습니다.

정직한 요약은 자막이 주는 그대로입니다. 환경 변수는 가장 쉬운 길이고, 어디서나 통하고, 그만큼 잘 샙니다. 노출되면 비싸기보다 민망한 정도인 값에 쓰고, 회전이 곧 재시작이라는 것을 알고 쓰세요. 그리고 어떤 값을 로그에서 지우려고 마스킹 규칙을 쓰고 있는 자신을 발견한다면, 그 값이 다른 경로에 속했다는 신호로 받아들이면 됩니다.
